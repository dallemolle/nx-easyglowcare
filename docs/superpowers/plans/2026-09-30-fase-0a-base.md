# Fase 0A: Base do projeto (plano de implementação)

> **Para agentes:** sub-skill obrigatória: superpowers:subagent-driven-development (recomendada) ou superpowers:executing-plans, para implementar tarefa por tarefa. Os passos usam checkbox (`- [ ]`).

**Objetivo:** subir a base Next.js multi-tenant com Postgres local no Docker, um helper de escopo por tenant provado por testes, o seed "EasyGlowCare" e a página pública `/[slug]`.

**Arquitetura:**
- **App:** Next 16 (App Router) usando sempre `@neondatabase/serverless`. Em dev, o driver fala com um `local-neon-http-proxy` que fica na frente do `postgres:17` no Docker.
- **Ferramentas:** drizzle-kit, seed e testes usam `pg` por TCP.
- **Isolamento:** feito pelo `tenantScope` (aplicação) e reforçado por FKs compostas (banco).

**Stack:** Next.js 16.3, React 19, TypeScript strict, Tailwind 4, shadcn/ui, Drizzle ORM + drizzle-kit, @neondatabase/serverless, pg, Zod, Vitest, pnpm 12, Docker Compose.

**Spec:** `docs/superpowers/specs/2026-09-30-fase-0a-base-design.md`. Leia antes de começar; este plano não repete as decisões dela.

## Restrições globais

- **Preservar `CLAUDE.md` e `ROADMAP.md`:** o scaffold nunca sobrescreve esses arquivos. Eles só recebem as edições da Tarefa 8.
- **Next 16:** antes de escrever código Next, leia o guia relevante em `node_modules/next/dist/docs/` (regra do `AGENTS.md`). `params` é uma `Promise`.
- **TypeScript `strict: true`;** proibido `any` explícito fora dos tipos genéricos do Drizzle.
- **Banco:**
  - toda tabela de negócio tem `tenant_id uuid not null` com FK `on delete cascade` para `tenants`, índice começando por `tenant_id` e `unique(tenant_id, id)`;
  - FKs entre tabelas de negócio são compostas `(tenant_id, x_id)`;
  - dinheiro é `integer` em centavos;
  - datas são `timestamptz`;
  - Drizzle com `casing: "snake_case"`.
- **Imports do client:** só `src/server/services/tenants.ts` importa `@/server/db/client`.
- **Interface:** em pt-BR, moeda BRL, mobile first (375px).
- **Commits:** mensagens em português no imperativo, terminando com `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Branch `feat/fase-0-fundacao`.
- **Migrations:** nunca editar uma migration já aplicada.

## Foco de revisão

1. **Slug fora do padrão na URL** (`/EasyGlowCare`, `/favicon.ico`, `/a%20b`, 200 caracteres):
   - maiúsculas são normalizadas e encontram o tenant;
   - qualquer coisa fora de `^[a-z0-9]+(-[a-z0-9]+)*$` (até 63 caracteres) devolve `null` sem consultar o banco, e a página dá 404.
   - Teste na Tarefa 5.
2. **Catálogo vazio:**
   - categoria sem serviço ativo não aparece;
   - tenant sem nenhum serviço ativo mostra "Catálogo em breve.";
   - serviço com `is_active = false` não aparece.
   - Testes na Tarefa 5 (`getPublicCatalog`) e na Tarefa 7 (página).
3. **`scope.insert(table, [])`:** devolve `[]` sem executar query, em vez do erro do Drizzle. Teste na Tarefa 4.
4. **`scope.update` com um `set` que só tem `tenantId`:** lança `TenantScopeError("update sem campos após remover tenantId")`, em vez do erro genérico do Drizzle. Teste na Tarefa 4.
5. **`DATABASE_URL` ausente ou inválida:** `env.ts` lança um erro que cita o nome da variável, antes de chegar ao driver. Teste na Tarefa 2.

**Arquivos:**

**Interfaces:**

  - `class InvalidTenantIdError extends TenantScopeError`
  - `type TenantScope`, com os métodos abaixo

Métodos do `TenantScope`:
- `tenantId: string`
- `where(table, ...conds: (SQL | undefined)[]): SQL`
- `select<T extends TenantTable>(table: T, ...conds): Promise<T["$inferSelect"][]>`
- `insert<T>(table: T, values: Omit<T["$inferInsert"], "tenantId"> | Omit<…>[]): Promise<T["$inferSelect"][]>`
- `update<T>(table: T, set: Partial<T["$inferInsert"]>, ...conds): Promise<T["$inferSelect"][]>`
- `delete<T>(table: T, ...conds): Promise<T["$inferSelect"][]>`

- [ ] **Passo 1: escrever os testes que falham**

No `beforeEach`: `resetDb()`, cria os tenants A e B e uma categoria em cada um (`catA`, `catB`) via `getTestDb()` direto, e monta `const a = tenantScope(getTestDb(), A.id)`.

| Teste | Asserção |
|---|---|
| `select isola por tenant` | `(await a.select(serviceCategories)).map(r => r.id)` é igual a `[catA.id]` |
| `insert força o tenant do escopo` | `a.insert(serviceCategories, { ...dados, tenantId: B.id } as never)` → a linha retornada tem `tenantId === A.id` |
| `insert com array vazio não consulta` | `await a.insert(serviceCategories, [])` é igual a `[]` |
| `update não alcança outro tenant` | `a.update(serviceCategories, { name: "x" }, eq(serviceCategories.id, catB.id))` → `[]`; a `catB` mantém o nome original |
| `delete não alcança outro tenant` | `a.delete(serviceCategories, eq(serviceCategories.id, catB.id))` → `[]`; a `catB` continua existindo |
| `update não move a linha de tenant` | `a.update(serviceCategories, { name: "y", tenantId: B.id }, eq(serviceCategories.id, catA.id))` → a linha tem `tenantId === A.id` e `name === "y"` |
| `update só com tenantId lança erro` | `a.update(serviceCategories, { tenantId: B.id })` rejeita com `TenantScopeError` e mensagem "update sem campos após remover tenantId" |
| `tenantId inválido` | `expect(() => tenantScope(getTestDb(), "x")).toThrow(InvalidTenantIdError)` |
